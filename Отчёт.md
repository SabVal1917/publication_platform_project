# Отчёт: алерты сервиса

## Реализация

Переиспользованы метрики backend, пробера и VictoriaMetrics из предыдущих работ.

vmalert вычисляет правила каждые 15 секунд и передаёт алерты в Alertmanager.

Alertmanager отправляет JSON-уведомления в локальный вебхук, который пишет их в stdout.

Для демонстрации используется готовый образ `blog-backend:sre-demo`.

## Условия алертов

| Алерт | Уровень | Условие | Обоснование |
| --- | --- | --- | --- |
| `BackendHigh5xxCount` | critical | >=5 ответов 5xx за 5 минут, `for: 1m` | Серия серверных ошибок мешает работе пользователей |
| `ProberUnavailable` | critical | Неуспешная проба, недоступные метрики или проба старше 30 секунд, `for: 1m` | Контроль доступности API, чтения из БД и самого пробера |
| `BackendHighLatency` | warning | p95 за 5 минут >500 мс, минимум 20 успешных ответов на маршрут, `for: 2m` | Граница быстрых ответов из SLO; минимум запросов уменьшает шум |
| `BackendGoHeapHigh` | warning | Занятая Go heap >64 MiB, `for: 2m` | Половина лимита контейнера 128 MiB, запас для остальной памяти процесса |

Два алерта относятся к метрикам сервиса, один к рантайму Go через GoCollector.

Для 5xx используется `publication_platform_http_requests_total{status=~"5.."}` и `increase(...[5m])`.

Для p95 используется `histogram_quantile` по `publication_platform_http_request_duration_seconds_bucket`.

HTTP-правила учитывают `/api/.*`, кроме `/api/ping`; latency учитывает только ответы 2xx/3xx.
Пробер проверяется по `up`, `publication_platform_probe_success` и `publication_platform_probe_timestamp_seconds`.

Отсутствие метрик пробера также вызывает алерт. Память берётся из `go_memstats_heap_alloc_bytes`, это heap, а не весь RSS.

## Конфигурация

Правила: `k8s/monitoring/alerts/rules/service.yaml` и `runtime.yaml`.

Alertmanager: `k8s/monitoring/alerts/alertmanager-config.yaml`.

Манифесты vmalert, Alertmanager и webhook: `k8s/monitoring/alerts/`.

Уведомления группируются по имени алерта, namespace, сервису и уровню.

Первая отправка через 10 секунд, изменения группы через 30 секунд, повтор через час.
`send_resolved: true` включает уведомления о восстановлении.

## Развёртывание

В существующем minikube с VictoriaMetrics:

```bash
kubectl apply -k k8s/monitoring/alerts
kubectl port-forward -n monitoring svc/vmalert 8880:8880
kubectl port-forward -n monitoring svc/alertmanager 9093:9093
```

Каждый port-forward запускается в отдельном терминале.
Правила: <http://localhost:8880/vmalert/groups>; Alertmanager: <http://localhost:9093/#/alerts>.
